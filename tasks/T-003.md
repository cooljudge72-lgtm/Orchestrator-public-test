## Goal
The owner submits a task once. Claude implements it, Codex independently reviews the exact pull
request head, Claude fixes findings (at most two rounds), Codex re-reviews, and the owner is
notified once with `READY_FOR_OWNER`. No prompts, files or reports are relayed by hand. Only the
owner can approve the merge, and nothing merges automatically.

## Acceptance criteria

### Stage 1 — planner (`orchestrator/state.py`)
1.1 **Strict gates.** `allowed_paths`, `claim_verified`, `ci_passed` and `reviewer_independent`
    default to `False`. Each gate that an event depends on must be exactly the boolean `True` for
    that event; an omitted, `False` or merely truthy value blocks it. A non-boolean value in
    **any** gate always blocks, even on an event that does not depend on that gate. Gate
    dependencies: `CLAIM_ACCEPTED` and `IMPLEMENTED` need `allowed_paths` and `claim_verified`;
    `REVIEW_CHANGES` also needs `reviewer_independent`; `REVIEW_APPROVED` needs all four.
1.2 **Exact head binding.** A review event counts only for the snapshot's current head SHA
    (40 lowercase hex); an implementation must produce a new head.
1.3 **Actors.** Claim acceptance only by `owner`, implementation only by `claude`, review only by
    `codex` with `reviewer_independent is True`.
1.4 **CI.** Approval requires `ci_passed is True` for the current head.
1.5 **Revision cap.** At most 2 change requests; a third blocks.
1.6 **Terminal BLOCKED, no merge.** BLOCKED is terminal; `MERGE` and unknown events block.
1.7 **Repository.** Only `cooljudge72-lgtm/Orchestrator-public-test`.
1.8 **Tests.** Synthetic tests for each item, including omitted, false, malformed and truthy gate
    values for every gated event.

### Stage 2 — synthetic coordinator (`orchestrator/cycle.py`)
2.1 Reviews bound to repository, PR number, head SHA and the configured reviewer identity.
2.2 Event ids validated before they are consumed; identical retries ignored, conflicting reuse
    blocks.
2.3 Adapter failures and malformed results fail closed to BLOCKED; an active readiness notice is
    withdrawn.
2.4 De-duplication documented as single-instance, in-memory only.
2.5 Local output never overwrites, never follows symlinks, never leaves a partial report.
2.6 **Open blocker S2-1:** the coordinator must not report path verification as successful before
    any path evidence exists (it currently passes `allowed_paths=True` for `CLAIM_ACCEPTED`).
    Stage 2 cannot be accepted for T-003 until this is resolved and reviewed.

### Stage 3 — read-only GitHub adapter
3.1 **Single task.** Act only when `refs/lockcheck/task-T-003` exists and `pilot-status` claim
    provenance checks pass.
3.2 **Reviewer provenance.** Verdicts only from the configured reviewer identity
    (observed: `chatgpt-codex-connector[bot]`), never from the implementer
    (`forclaudeacc-maker`) or any identity that can push to the PR branch.
3.3 **Exact commit.** A review counts only if its `commit_id` equals the current head and it was
    submitted after that head became current.
3.4 **No A→B→A.** Each new head must descend from the previously reviewed head; a head SHA already
    seen on the PR is rejected and earlier verdicts or CI results are never reused for it.
3.5 **Idempotent, restart-safe.** Keys (repository, PR, head SHA, review id) are read back from
    GitHub; restarting never repeats a fix or the readiness notification.
3.6 **Verdict format.** Codex currently posts `COMMENTED` reviews with the verdict in the text;
    the adapter must parse it fail-closed (unknown or ambiguous verdict blocks).
3.7 **Owner approval gate.** The `main` ruleset's required approval (stale approvals dismissed,
    latest push approved) is a precondition; the adapter never approves or merges.
3.8 **Limits and kill switch.** No action while the PR carries `orchestrator-paused`; only existing
    subscriptions; at most 2 correction rounds.
